검증된 실정보처럼 노출한 점**이 문제다.

복구 시에는 예시/미확인 상태를 명시하고, 카피 덱의 결과·저장 경계를 실제 구현 수준에 맞춰야 한다.
저장은 승인된 지속성 범위로 구현한 뒤 새로고침/재진입을 검사하고, 검색·필터·상세·신청 준비는
실제 과업 전이로 검증해야 한다. 공공기관 인증·제출·접수 완료를 가짜 성공 화면으로 만들면 안 된다.

## 원인과 이번 수정

### 1. 지침 층

수정 전 one-shot 축약 흐름에는 선택된 Writer/Typesetter/후보 작업이 빠져 있었다.
새 지침은 라우트의 선택 단계/의존성이 실제 실행 기준임을 명시한다. PRD를 카피 덱으로,
구현 후 메모를 사전 구성 계약으로 대체하지 못한다. 오류를 없애려고 위험도/제품 분류를
바꾸지 않는다. 선택된 병렬 Writer/Scout 작업은 허용하고, 카피만 고치는 작업에 새 리서치를 강제하지 않는다.

### 2. 검증 층

`omd guard production --json`은 인증된 현재 route pointer를 해석하고 다음을 확인한다.

- 선택 단계의 비어 있지 않은 산출물과 현재 프로토콜 전달 기록.
- 기존 production brief가 요구하는 두 리서치 lane, 화면별 적용표, 계획 사실, 로케일 등의 검사.
- 제품 프레임의 UX/과업 매트릭스와 new-product의 product/mixed 분류 일치.
- 카피 덱 구조·사실 참조, 선택된 카피 워크플로의 현재 덱 hash에 대한 CLEAN 리뷰.
- 실제 해석 가능한 보드와 그 보드 hash에 연결된 디자인 가설.
- 구성 계약의 내용·현재 입력 fingerprint, 선택된 후보의 current pointer와 완전한 파일 집합.
- 특정 파일에 대한 라우트 허용 경로. design-only는 앱 구현을 허용하지 않음.

기존 production reference gate는 호출자가 역할 값을 주지 않으면 돌아가지 않았고, route pointer를
직접 projectMode 레코드로 읽었다. 이 존재 검사형 함수를 현재 입력 검증으로 교체했다.

`omd guard completion --json`은 설계 입력을 재검사하고 실제 slop loop를 먼저 확인한 뒤,
기존 final evidence/독립 리뷰 권한/최종 화면 범위 검증으로 이어진다. design-only는 design-check로
분기한다. 로컬 CLI 접근을 허용하되 리뷰 권한 검사를 제거하거나 임의 서명하지 않는다.

### 3. Pi 실행 층

- `tool_call`: 기본 write/edit의 앱 파일 쓰기와 임의 bash 실행 직전에 production gate 실행.
- `.omd/.cache/` 입력과 직접 소유한 문서는 작성 가능. route/권한/체크 기록/최종 근거 등의
  CLI 소유 파일은 기본 쓰기로 위조 불가. 경로 이탈·심볼릭 링크 쓰기도 차단.
- `message_end`: 실제 OMD 실행의 최종 완료 초안을 gate로 검사하고, 실패 시 미완료 상태로 교체.
- 소스 작성 시도가 있었던 턴의 수정 가능한 실패는 실제 사용자 입력당 최대 두 번의 custom follow-up으로 수정·재검사.
  리서치/문서만 다룬 턴은 남은 구현 범위를 자동 실행할 권한이 아니다.
  사용자 입력을 위조하지 않으며, 사용자 중단·사실 부족·권한 문제는 자동 재시도하지 않음.
- 프로젝트별 CLI 큐로 같은 프로젝트의 병렬 발행 lock 충돌 방지. 다른 프로젝트는 독립 실행.

## 검증과 한계

회귀 테스트는 실패 사례만이 아니라 정상 카피 전용 경로, 실제 로컬 CLI 호출, design-only 분기,
write/edit/bash 차단, 리서치 복구 가능성, 현재 리뷰 hash, 후보 stub 거부, 프로젝트별 큐,
실패 뒤 큐 복구, 취소, 후속 작업 횟수 제한과 권한 실패 시 중단을 포함한다.
소스 작성 경계 보강 전 로컬 검증: `npm test` 총 2,708개 중 2,706 통과·0 실패·기존 조건부 2개 skip
(비-Darwin 전용 검사 1개와 외부 관찰자 서명 권한 필요 검사 1개),
`npx tsc --noEmit` 통과, `npm run build` 통과, 스킬 quick validation 통과.
`pi install .`로 개발본을 적용했다. 이미 열려 있는 Pi 세션은 `/reload`가 필요하다.
로컬 Pi 0.85.1의 실제 extension loader에서도 로드 오류 0, 다섯 이벤트 훅 등록,
미승인 write 차단과 최종 미완료 응답 교체를 확인했다. 유료 모델 호출 없이 호스트 로더와 실제 CLI를
통과시킨 smoke test이며, 사용자의 다음 전체 설계 실행을 대신하는 검증은 아니다.

이 검증은 **자동 미적 품질 보증이 아니다**. 일반 Markdown 산출물의 존재/현재성은 판단의 정확성이나
실제 관찰을 스스로 증명하지 않는다. 독립 리뷰·브라우저 동작 증거가 여전히 필요하다.
Pi 훅은 OS 샌드박스가 아니며 외부 프로세스/별도 쓰기 도구 전체를 통제하지 않는다.
스트리밍 초안은 message_end 이전에 보일 수 있다. 지원 API는 로컬 Pi 0.85.1 문서와 대조했다.
호환 fork는 최종 메시지 교체 동작도 지원해야 한다.

test-011 앱과 기존 증거는 감사 과정에서 소급 수정하거나 완료 처리하지 않았다.
이번 빌드로 기존 route를 검사하면 build/skill 결합이 오래돼 ROUTE_AUTHORITY_REQUIRED가 난다.
이를 인증 키 삭제나 가짜 activation으로 우회하지 않는다. 원래 사용자 요청 전체와 범위를 복원한 뒤
현재 버전으로 route validate/classify를 하고, 누락된 설계 작업부터 다시 수행해야 한다.

## 재실행 체크리스트

1. Pi에 로컬 개발본 적용 후 `/reload`. 새 테스트가 가장 명확하며, test-011을 재개하면 원래 PRD를 먼저 대조한다.
2. 상세 PRD를 세 화면짜리 요약으로 줄여 요구 기능을 누락하지 않는다. 우회된 editorial 프레임을 재사용하지 않는다.
3. 무료 접근 가능한 앱 디자인 사례와 유사 서비스 플로우를 별도 조사·캡처·발행하고, 각 화면의 채택/배제 결정을 기록한다.
4. Writer → 현재 copy review, 선택된 Typesetter, Composer, 후보 선택을 실제 수행한다. 막히면 근거를 고친다.
5. production gate 통과 후 구현. 저장/검색/신청 준비의 실제 전이와 접근성을 브라우저에서 확인한다.
6. slop checkpoint → 이미지 판정 → 수정 또는 타당한 제외 → 같은 범위 재검사. 최신 소스와 최종 viewport에 결합한다.
7. 완료 gate가 통과한 범위만 완료라고 보고한다. Pi에서 독립 리뷰 권한이 없으면 그 제한을 분리해 보고한다.

릴리즈/버전 변경은 하지 않는다. 개발 → Pi 적용 → 사용자 테스트 순서를 유지한다.
