## 재시도 전·도중의 프레임워크 수정

### 실행 요구사항과 화면 요구사항 분리

`taskOutcome.executionRequirements`는 원래 지시문과 해당 지시를 집행하는 기존 호스트
게이트를 함께 보존한다. 화면에서 확인하는 `mustHave`, `mustNotHave`,
`completionEvidence`의 검사는 그대로 유지한다. 최초 경로 게시 전에 분리하며,
실패한 제품 행동을 실행 요구사항으로 옮겨 통과시키는 수단이 아니다.

허용 게이트는 범위·쓰기 권한·활성화·소스 봉인·독립 리뷰·최종 증거·사용자 모델 소유권·
최종 사전검사로 닫혀 있다. 임의 판정이나 네이티브 설치 성공은 이 목록에 넣을 수 없다.
실행 요구사항은 원문 경로 해시에 포함되며, 시각 리뷰 입력에서는 제외된다. 최종 사전검사에서
현재 최종 증거와 게시 전제조건이 모두 통과한 다음에만 검증 결과를 반환한다.

관련 소스는 `core/brief/execution-requirements.ts`, `core/brief/task-outcome.ts`,
`core/completion/preflight.ts`, `core/runtime/final-render-review.ts`다. 스키마와
Framer 안내도 함께 수정했다. 양성·음성 파서, 원문 해시, 실제 브라우저 행동,
성공 전 최종검사 거절과 성공 후 확인, 리뷰 변경 후 거절을 회귀 검사한다.

### 역할의 실제 브라우저 명령 안내

Scout·Typesetter의 호스트 문맥에 실제 브로커 허용 목록에서 도출한 명령을 제공한다.
대화형 브라우저 도구가 없다는 이유로 이미 허용된 CLI 캡처까지 불가능하다고 판단하지
않도록 수정했다. 별도 브라우저 실행, 사적 세션 가져오기, 권한 확대는 허용하지 않는다.
명령 실행과 실제 저장된 캡처가 성공해야 하며 doctor 성공만으로 획득 성공을 주장하지 않는다.

### 보이는 자식 요소가 사라지는 구조 추출 오류

현장 점검의 참고 수집은 실제 필터 목록의 PNG를 저장했으나, 두 크기의 구조 데이터에는

`SidebarPageLayout` 요소가 `display: contents`인 것을 확인했다. 기존
`core/ir/dom.ts`는 폭·높이 0인 요소에서 탐색을 끝내므로, 그 요소의 보이는 자식들도 버렸다.

수정은 상자 없는 중간 요소의 **요소 자식**을 가장 가까운 측정된 부모에 연결한다.

없는 선택 루트를 여러 가짜 루트로 바꾸지도 않는다. 직접 텍스트만 가진 상자 없는 요소의

독립된 로컬 브라우저 fixture에서 수정 전 두 검사가 실패했고, 수정 후 새 검사 3개와

### 현장 점검·설치형 앱: 구조 후보 선택 후 제작 진입 차단

후속 Framer와 Scout는 실제 관찰 가능한 구성 요소 범위를 다시 정하고 해당 범위의 새 캡처를 수집했다. 제품의 T1–T9와 기능 요구사항 23개는 유지했다. 새 참고 조합과 세분화 검사, `continuous-checklist` 선택, Composer 구성 검사, Typesetter 토큰 검사, 제작 전 결정 검사가 통과했다. 이전의 중복·출처 집중·상태 불일치·시간 초과 기록은 보존했다.

두 Sketch가 만든 후보는 호스트의 OMD 명령으로 렌더·검사했다. 자식 환경의 Chromium 실행 실패는 별도로 남겼다. 첫 후보 s01은 검사한 28개 동작·48개 확인 항목을 통과했다. 두 번째 s02는 입력 흐름에서 동작 3개와 확인 항목 6개가 실패했고, 기록 필터 검사 통과로 이 실패를 덮지 않았다. 구조 Eye는 28개 이미지를 검토했다고 보고하고 s01을 선택했다. 일반 프로토콜 등을 지정 목록 밖에서 추가로 열람했다는 검토자의 한계도 그대로 보존했다. 이 결과는 구조 후보 선택 의견이며 전체 기능·최종 디자인·OS 승인과 구분한다.

제작은 후보 선택 기록 연결에서 멈췄다. `omd candidate select` 게시 명령은 있지만, 공개 `omd schema`에는 `candidate-selection-pointer`, `ux-models`, `noun-swap-test`, `candidate-selection` 계약이 없다. 필요한 보조 기록의 작성·게시 계약도 발견되지 않아 원래 작성자의 반환 기록을 정규 후보 입력으로 연결하지 못했다. 생산 brief는 `selected production input missing: candidate-generation`을 반환한다. 부모의 코드 확인에서도 포인터 게시 함수와 네 필수 파일 검사는 존재하지만 해당 공개 입력 계약은 누락된 것을 확인했다.

Hand는 실행하지 않았으므로 모바일 생산 코드, Swift·Java 컨테이너, 빌드 파일, 설치 바이너리가 없다. final-v2도 없고 terminal preflight는 실패했다. 선택한 후보와 미실행 Hand 전달 자료는 [후속 실행 차단 기록](/Users/lyu/01_Project/01_Projects/OMD-Evaluation-Runs/product-ux-20260912.9zQGII/field-inspection-mobile/.omd/production-blocker-runtime3.md)에 보존했다. 이 공개 계약과 게시·검증 경로를 보완한 뒤 담당 작성자의 기록을 연결하고 실제 앱 제작·검증을 다시 이어가야 한다.

재실행 중 확인한 추가 준비 단계 문제는 프레임워크 회귀 결과와 구분한다.

- 두 실행의 첫 Scout는 실제 브라우저 명령을 수행했지만, 검색 도구 미연결과
  접근 가능한 참고 상태 부족으로 조합을 게시하지 못했다. 역할 프로세스의 종료 코드
  0은 해당 참고 단계의 성공을 뜻하지 않았다. 후속 단계는 실패한 검사를 통과로 처리하지 않았다.
- 공식 가이드에서 작업 흐름 근거를 보완한 뒤 두 작업의 benchmark가 게시됐다.
  가이드의 작업 순서는 화면 배치의 측정 증거와 구분했다.
- Support Framer가 선택한 진입 작업 ID와 Scout benchmark의 ID가 달라 평가 계획이
  거절됐다. Framer가 기존 사용자 작업을 유지한 채 진입 계약을 정렬한 뒤 계획이 생성됐다.
- 초기 참고 계획에는 목적 제품의 전체 상태를 외부 제품에서도 요구한 항목이 있었다.
  해당 계획의 소유자인 Framer가 측정 가능한 구성 요소 관계와 그 한계를 명시해 수정했다.
  입력 보존·누락 복구·모바일 답장 등의 목적 제품 요구사항은 삭제하지 않았다.
- 현장 점검의 처음 게시된 프레임에는 필요한 기능 요구사항과 진입 증인이 빠져 있었다. Framer가 보충했다. 글자 시편의 크기 단계와 토큰 규칙 충돌은 Typesetter가 수정했고, 새 Eye의 글자 시편 한정 검토를 통과했다. 이 결과는 제품 화면의 최종 리뷰가 아니다.

이 준비 과정의 실패·복구 기록을 제품 사용 실패율이나 디자인 품질 점수로 환산하지 않는다. 참고 캡처와 글자 시편도 생산 화면으로 제시하지 않는다.
