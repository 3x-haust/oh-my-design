# Design language translation v1

Native Pi selects a grounded reading autonomously. Its publisher refuses a new
`needs-clarification` record before any pointer mutation with
`DESIGN_LANGUAGE_AUTONOMOUS_SELECTION_REQUIRED`; repair the input with `chosenId`
and an observed decision reason. Native decisions record `decisionActor: harness`,
not user approval. Explicit developer interviews run after rendered output and
are not a translation or production prerequisite. Historical question records
remain readable and hash-bound; this does not manufacture an answer to them.

After an authorized route change, the coordinator must author a current-contract input and obtain a current reading judgment before republishing. The translation publisher verifies historical bytes without requiring their route context to remain current; it never promotes that historical interpretation. A pending question binds an answer only within the same request and source contract. A changed context requires a fresh interpretation, not an answer to the old question. Consumers continue to reject stale translations, and corrupt historical records or stale replacement inputs refuse without changing the pointer or application source.

Preserve the complete user request. After domain analysis, the coordinator may propose a `design-language-input-v1` reading of casual Korean or English feedback. The lexicon in `core/theory/design-language.lexicon.v1.json` supplies contextual hypotheses, not universal taste laws. A model-proposed reading uses the same registered metrics. `omd language translate --input ...` publishes an exact source-contract-bound, content-addressed interpretation; `omd language check` reads it. Never use adjectives alone as a prescription or keywords alone as evidence.

The design lane searches English names for parts and mechanisms while the domain lane retains local market/service qualification. A pending historical interpretation may drive search, not production. Select the strongest task-grounded interpretation and explain the choice; uncertainty is not authority to ask for aesthetic approval. Legacy non-Pi question records remain readable only with their original admitted image digests and exact answer binding. A selected reading projects measured targets, destinations and its digest to art direction, composition and Hand. Reference pixels follow the separate bounded maker-image contract, never the language translation's prose or arbitrary thumbnail paths. Never copy named-product branding or let Hand rewrite approved copy. Keep a white canvas with distinct primary, secondary and accent roles as the default product reading; neither beige/editorial treatment nor 60-30-10 percentages are hard rules.

Feedback translation is not authorization to change application source. First measure the current native render at the same route, state and viewport; do not accept caller-authored baseline numbers. Bounded Hand repair follows existing write authority, then fresh native evidence, a passing movement check and existing independent refinement review. `omd feedback check` compares the native before/after scoped measurements and refuses no movement, lost destinations, and local scope-floor failures. It does not claim independent review or final task/accessibility/safety coverage: refinement checkpoint and completion revalidate the current signed production observations and Eye review. A better Eye preference cannot override unmet movement. A translation that rejects overall direction reopens art direction or composition; copy-tone readings instead reopen Writer and require a changed deck plus current CLEAN copy review. Copy-tone targets never appear in Hand's visual projection, and the copy-stage skip remains a skip rather than selecting a new stage. Selected route skips remain skips.

Before publishing the required `design-language-reading` judgment, run `omd schema ai-judgment --purpose design-language-reading --input <current-design-language-input.json> --json`. The starter validates that exact intake or feedback input against the current signed request and route before writing anything, then derives the judgment decision and `{ kind, textSha256, chosenId }` payload from the parsed input while preserving the authentic request quote and current source-contract digest. The coordinator must replace the starter reason with its own explanation; the starter is not an approval. Invalid or stale input refuses before changing the starter, application source, or design-language current pointers, and publication still requires the authorized signed judgment publisher.

Executable refusal codes: `DESIGN_LANGUAGE_INVALID`, `DESIGN_LANGUAGE_REQUIRED`, `DESIGN_LANGUAGE_UNGROUNDED`, `DESIGN_LANGUAGE_AMBIGUOUS`, `DESIGN_LANGUAGE_STALE`, `DESIGN_LANGUAGE_BINDING_MISSING`, `FEEDBACK_MEASUREMENT_REQUIRED`, `FEEDBACK_BASELINE_STALE`, `FEEDBACK_TARGET_UNMET`. Refused publication must not alter application source or current pointers. Advisory seed intervals are contextual, not universal aesthetic thresholds. `AI-looking` prompts inspection of concrete slop findings, never a claim about authorship.
