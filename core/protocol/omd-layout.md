# Project `.omd/` layout and retention

`core/layout/index.ts` is the path-by-path registry; `omd status --files` reports actual sizes and unclassified files. This document records *why* each class exists. New writers must register their paths and name a reader or decision use. The directory is a design record, not a dump of command output. File sizes below are expectations, not limits; inspect real projects with `omd status --files`.

| Family / schema examples | Writer and cadence | Reader / decision use | Typical size | Retention |
| --- | --- | --- | --- | --- |
| Human contracts: `domain-brief.json`, `frame.md`, `functional-requirements.json`, `acquisition-plan.json`, `scout.md`, `reference-analysis.json`, `reference-board.json`, `copy-deck.md`, `type-proof.md`, `composition.md`, `design.md`, `decisions.md`, `decision-graph.json`, `locale.json`, `tokens.json`, `attribution.md`, `reference-report.md`, `motion-spec.md`, `design-judgment.json`, `first-render-critic.json`, `runtime-design-system.json`, `runtime-design-system.md`, `probes/*.json` (declared plans), `moodboard.json|md`, `analysis.md`, existing design-system inventory, content grain/fit | Domain/Frame/Scout/Writer/Composer and review owners; one current artifact per stage or revision | Downstream roles, stage entry, composition/copy/reference gates and human reviewers; stores choices and their rationale, not a generated command transcript | Usually KB per file | Keep |
| Research: `refs/`, `discovery/`, `figma/`, `target/` | Reference acquisition and Figma/target capture; per source, state, viewport | Reference assembly, provenance and fidelity checks; source observations cannot be reconstructed from a summary | JSON KB; captures KB-MB each | Keep source receipts and pixels while cited |
| Current machine state: `route.json`, `depth.json`, `intent-current.json`, `art-direction.json`, `reference-*selection*.json`, `visual-measurement.json`, `surface-captures.json`, `selected-direction-evidence.json`, `source-seal.json`, `task-evidence.json`, `final-evidence-v2.json`, and other registered current pointers | Router, direction owner, browser runner, evaluators; replaced when the authorized decision changes | Stage gates and completion validate the current route, source, evidence and selection lineage | Usually KB per pointer | Keep |
| Immutable provenance: `intent-runs/`, `art-direction-runs/`, `evaluator-results/`, `pre-reference-selections/`, `settled-reference-selections/`, `motion-resolutions/`, `reference-handoffs/`, `discovery/`, `visual-measurements/`, `visual-measurement-ir/`, `visual-measurement-captures/`, `selected-direction-captures/`, `refinement/`, `first-render/`, `runtime-design-system/`, `task-evidence-runs/`, `final-evidence-v2-runs/`, `evidence/`, `slop/`, `observations/` and `final-review/`, workflow and reference-application/research records, learned rules | Stage publishers, signed reviewers and browser capture; one record per execution, lane or content digest | Current pointers, reviewers, `guard completion` and forensic audit verify exact inputs and outcomes; evidence-linked files are not disposable | JSON KB; captures and traces KB-MB, growing per run | Keep cited lineage |
| Other registered state: reference usage/coverage, task-flow and locale profiles, asset decisions, measured observation/attestation, `config.json`, `taste/`, `delivery.jsonl`, `stage-usage.jsonl`, `history.jsonl`, `craft.jsonl` | Responsible gate/owner; current file or append per delivery/check/decision | Downstream gates, status, coach and human review of chronology and decision provenance | KB per record; logs grow per event | Keep |
| Scratch: `.cache/` (including `.cache/probes/` output) | Role tasks, sketches, previews, renders and probes; per attempt | Intermediate role work and probe results; `scanProject` retains cache paths cited by durable records, including selected sketches | KB-MB per attempt | Ephemeral unless cited; `omd clean` lists safe entries |
| Legacy scratch: `framer-decisions/`, `writer-decisions/`, `refs/decisions/`, `refs/candidate-assemblies.json`, `briefs/` | No current writer | No current gate; `briefs/*.json` was read only in tests and `briefs/*.md` repeated `omd brief` output | Old briefs: two near-static files per stage, overwritten on entry/inspection | Remove with `omd clean --stale-records` |

`omd brief <stage>` and `omd brief <stage> --json` still compute current stage inputs on demand; `--check` still enforces stage entry. Neither persists a redundant snapshot. Retaining a brief *as evidence of what an owner saw* would require an immutable, invocation-bound delivery receipt; an overwritten view does not establish that provenance. Do not delete signed receipts, active pointers, or cache paths cited by durable evidence merely because they look generated. Unclassified paths block cleanup until classified.
