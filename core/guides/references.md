# Finding and using references

Read `omd pack protocol/reference-assembly.md` for capture rules when needed.

- Match references to the requested surface: populated task screens for product UI, finished
  service websites for marketing, populated reading/browsing surfaces for content. Gallery
  thumbnails, pattern libraries and design-system docs are discovery leads, not visual references.
- Use `omd ref browse`/`ref add` to inspect and keep complete originals: native-resolution images
  and complete 2x viewport captures, never pixel crops. Describe regions of interest on the whole image.
- Domain research (`ref navigate <url> --lane domain`) is about functions, content and flows of
  comparable services; it does not need screenshots and never substitutes for visual direction.
- Interaction states are references too. When the reference's hover, focus, pressed or open
  states carry its craft (buttons, rows, tabs, menus, inputs), capture each state as its own
  whole capture and label it. Never click anything that submits, purchases, signs in, deletes,
  downloads or navigates away to reach a state.
- Choose one coherent primary direction; supplemental references get limited named jobs.
- Resolve the reference's job from the user's actual request. A requested recreation or
  designated target requires faithful transfer. A discovered original for a new product teaches
  relationships; it is not an automatic clone target. Explain which source decisions fit this
  content and which belong to that source's own identity. Neither literal resemblance nor
  arbitrary difference establishes good design. Judge the integrated destination independently.
- Discovery and selection are different operations. Search multiple query directions and source
  families, inspect real complete screens, and compare different image/type relationships,
  composition and information structure before narrowing. The first three or four finds are not
  automatically an adequate search. Expand when candidates only repeat the same familiar layout;
  stop when additional exploration adds no material direction and the actual winner has a clear
  task-fit and craft advantage. A small retained set is useful after broad discovery, not instead
  of it. Record concrete retain/reject reasons in existing research records or working notes.
- A booking calendar can be excellent interaction/domain evidence without establishing an
  exhibition service's entire visual identity. Judge those jobs separately. Do not choose the
  primary visual original solely because it performs the same function.
- `omd pack cases` supplies locally installed, private source-native worked designer examples
  (empty when none are installed). They teach contextual
  decisions through actual words and original frames; they are not automatically eligible
  destination visual references or a style library to copy.
- Run `omd ref direction-review --json` when retained design captures need independent visual
  admission before they can guide production.
- Record what you actually consulted with `omd ref context` (see the ultradesign skill). Unknown
  or restricted rights mean the pixels are comparison material only; never ship reference pixels,
  copy or branding as product assets.

Report what was consulted, which source supplied which quality, and honest gaps. Never infer
quality or approval from a reference having been retained.

## Faithful reproduction

For a faithful-reference task, reproduce the primary's actual visual system before introducing a
new style: type family character and weight, type-to-space ratios, macro geometry, content density,
surface tones and complete control anatomy. Do not translate a light sans-serif original into an
invented serif "editorial" system, or preserve only its broad list/sidebar relationship. Work from
the actual whole pixels; inspect source runtime styles when available rather than guessing. Adapt
product content and functions inside that system, with explicit destination constraints governing
only the departures they actually require. Recheck the whole render after adaptation.
